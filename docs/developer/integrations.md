# 接入你已经做好的模块

[返回开发者入口](README.md)

先保留已有实现，再在边界做一次转换。常见情况如下：

| 已有模块 | 适配位置 | 交付给 TIDE 的结果 |
| --- | --- | --- |
| 模型服务、自己的 SDK/Agent 调用 | 提供方适配器 | 原始返回、实际失败及可观察的 usage |
| 分类器、规则模块、传感器解释 | 包的量测生产适配 | 包 schema 规定的量测，绑定实际输入来源 |
| 动画引擎、Live2D、游戏动作接口 | 宿主执行器 | 实际执行的内容ID、起止、完成/部分完成和打断原因 |
| 网页/屏幕/设备读取 | 外部事实入口与读取适配 | 实际读到的内容、时间、对象和可见范围 |
| 数据库或现有聊天记录 | 存储/历史适配 | 正式事件及其来源关联；旧文本不自动具备数值记忆参数 |

## 已有模型调用：先跑一次真实的本地适配

```powershell
python -B -m examples.existing_provider
```

[示例源码](../../examples/existing_provider.py) 的 `ExistingClientTransport` 复用现有 `ChatTransport` 请求配置和 `ProviderGateway` 生命周期，只替换实际调用函数。离线函数接收模拟观测分数，返回两个量测字段；Provider 校验完成后，数据交给独立小包结算。它不是一次真实 LLM 测试。

将 `completion` 换成你已有 SDK 的调用函数即可复用这个边界。函数输入是本次请求 payload（`model/messages` 等），返回 Chat Completions 形状的 JSON。若 SDK 已返回该形状，直接转普通字典；若只返回字符串，包装为唯一一个 `choices` 项，正文放在 `message.content`，完成原因按实际结果填写。SDK使用的真实模型、地址和绑定配置保持一致。

量测模型的正文需满足**当前包**规定的 JSON 合同；表达模型需满足当前产品的表达合同。接上网络调用只代表提供方可用，不代表任意自然语言输出都能当作正式量测。不要把 Runtime 当前根状态随意附加到量测提示词；需要的参考由包的正式输入定义决定。

提供方原始返回与解析是两个阶段。`ProviderGateway` 保存调用与解析结果；已有 SDK 报错时示例适配器生成内容无关的失败，不把密钥或错误正文搬进公共日志，不做自动重试。换真实 SDK 后需要单独验证模型格式、超时和费用；本例没有测试这些外部服务。

仅使用普通兼容HTTP服务，可直接配置 [ChatTransport/ProviderGateway](../../petlab_app/providers.py)，无需复制示例类。它们目前位于产品提供方模块；更底层共同协议在 [framework/provider_host.py](../../framework/provider_host.py)。

## 已有动画：让执行器返回实际结果

```powershell
python -B -m examples.existing_player
```

[示例源码](../../examples/existing_player.py) 用一个 `play_tail(is_cancelled)` 回调接已有播放器。你主要替换 `MemoryPlayer.play_tail`：在自己的引擎中播放，结束后返回实际播放量、跟踪引用、状态和打断来源。`MemoryPlayer` 只记录内存帧，不是立绘生成器。

`ExistingPlayerExecutor` 提供现有 `execute_guarded()` / `execute_composite()` 形状，产生 `ExecutionOutcome`，并调用原 `validate_outcome()`。演示完整播放、播放两帧后停止、播放前取消以及无资格无选择。它只支持**单个、无语言的玩尾巴动作**。若你的前端同时支持表情/讲话或连续动作，扩展同一个执行器的通道与依赖支持，参考 [DesktopExecutor](../../petlab_app/desktop_view.py)；不要静默忽略不支持的子项。

执行器负责事实，不决定心理量或抢先让对方接受。前端返回一个 `ExecutionOutcome` 也还不是正式记忆：将执行器交给产品的 `interact/resume` 或既有行为入口，才能继续来源/取消检查、执行提交、输出量测与历史归档。示例的 `memory_committed: false` 明确表示没有跑这段产品闭环。

技术失败、用户接触、来源失效应保留不同原因。已经开始但没播完，返回部分执行；能确认零效果才按取消处理；效果不确定时保留原日志进入恢复，避免重复播放或重复执行外部操作。

## 新输入与外部工具

已有传感器先产出有界事实摘要，再走对应包的输入子类。屏幕区域、坐标、URL和工具来源是客观信息；量测、资格与动作候选继续归包。每帧采样不逐条入记忆，持续内容按既有区间/观察边界聚合。

桌宠现成输入类型和接入入口见 [桌宠扩展](desktop.md)。联网、屏幕识别、付费工具应由你的产品明确配置和可见范围；这里只说明接入职责，当前仓库没有已上线的屏幕识别模块。

## 常见接入排查

| 现象 | 先查哪里 |
| --- | --- |
| 返回有文字但解析失败 | 实际请求的 codec 版本、原返回字段、完成原因 |
| 有候选但不动作 | 原资格、正式词元、候选匹配与宿主能力；候选不保证被选择 |
| 已执行但历史缺失 | 实际回执→提交→输出量测→归档分别到哪一步 |
| 网络慢时动画也卡住 | 前端循环与后台执行是否分开，前端是否等待模型 |
| 恢复后时间错误 | 是否有未结算事件被后续规划越过，是否混用发生时间/处理时间 |

诊断用实际阶段和来源定位。调用耗时、Provider解析、记忆召回、Writer交付与真实显示是不同事实。
