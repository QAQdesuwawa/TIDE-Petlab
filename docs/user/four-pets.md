# 四只桌宠（技术 Alpha）

alpha.504 源码提供四实例入口。默认启动仍是双宠；旧 Release 附件不包含这个入口。这里说明四宠的小规模验证范围，长期无人值守的群聊仍待验证。

复用同一套鲸鱼素材和角色定义，分别创建大肥鱼、小肥鱼、三肥鱼、四肥鱼；每只使用独立Actor、记忆与针对不同对象的关系状态。名称不同不代表已经分别量测出四套性格。

在当前源码目录、已安装依赖后，用自己的配置和新的工作区启动：

```powershell
.\launch_multi_pet.ps1 -Config "你的配置.json" -Workspace "output/four-pets" -PetCount 4
```

工作区必须与原双宠目录分开。再次用同一路径、原配置启动时，省略 `-PetCount` 会沿存档恢复原人数；不能把已有双宠工作区改成四人。临时密钥的保存方式仍沿原设置，不在命令里填写密钥。

右键任意角色可选择对该角色公开说、同时对所有角色公开说或与当前角色私聊。公开的可见范围和明确叫谁回应是不同的：其他角色听见后仍按原资格决定反应。讲话、可见表情与实际动作沿既有公开投递，内心思考保持私有。

alpha.506 修正了主动发言选中用户时被默认归为私聊的问题：普通定向讲话仍按公共受众投递，其他桌宠可以听见。显式私聊及其当前会话内的续话仍保持隔离，旧已封存目的地不改写。走近、转头或提到某个名字都不自动改变可见权限；当前尚未提供自主NPC悄悄话动作。

四宠首阶段验证交流、视线、走近、拖动与打断。原双宠的饭碗交接场景保留双人定义，四宠入口暂不启用饭碗菜单；尚未扩展多组道具与多人联合动画。

正式四窗口已用官方 Flash 做小规模验证：一次公共介绍后，四只先回应用户，随后两条针对其他角色的回应实际执行。总计22次模型请求，包括首次格式错误修复后从原来源继续；没有重试成功请求、强制接话或降低开口门限。另两条生成的后续回应在测试停止时取消，未算作执行。这证明短链可成立，尚不证明能长期持续自然群聊。

原生离线测试验证四个独立后台进程、第四只的拖动、私聊只进入接收者存档，以及关闭后恢复原四个身份。离线提供方只证明接线，不证明语言质量。多角色已选记忆的重复属性按卡内分组共享，保留独立原文、时间、编号和来源；不改变召回集合或数值计算。

真实服务的费用与等待时间随实际量测/表达请求增加，听见一段话不意味着每条关系都必须生成一轮回复。首次试用建议先发一句公共介绍，观察它们是否接续，再决定是否录制；当前没有附带宣传录像。

### 与同伴说悄悄话
右键角色，在“同伴交谈方式（不触发开口）”中选择与某位同伴公开交谈或说悄悄话。这个选项只改变交谈方式：角色仍自行选择对象并通过原开口资格，不会点击后必然讲话。

私语会先走近，再说话。途中拖动角色或移走目标会取消未说的话。其他桌宠仍能看到走近过程，空闲时可以看一眼并保留动作记忆，但收不到私语正文。人类与桌宠的私聊入口不变。


### alpha.524 源码更新

正式四窗口已验证接话、旁观和拖拽后的恢复。沉默不代表画面冻结：低频待机姿态使用当前对象最近正式保留的心情，只改变本地表现，不触发开口、量测或记忆。正式动作和鼠标接触优先。连续转身沿已完成朝向继续；默认素材更新为 `deepseek-bound-original-face`。长期无人值守及所有多人场景仍属 Alpha 验证范围。
