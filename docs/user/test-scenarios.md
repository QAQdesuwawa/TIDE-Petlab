# 可运行的功能样例

这套合成样例验证当前创建、旧聊天重建、正式记忆与表达交付的接线。模型返回由离线夹具提供，使用真正的包、ProviderGateway、来源检查、结算和恢复；不需要密钥、本地模型权重或外网。它不会打开桌宠窗口，也不会操作已有角色。

## 一次跑完

先按首页安装桌宠依赖，然后在仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe -B -X utf8 -m examples.petlab_scenarios
```

命令在当前目录的 `output/petlab-examples-随机编号/` 下生成独立资料，输出 `report.json` 的完整路径。也可以加 `--output "output/my-scenarios"` 指定一个尚不存在的目录。已有目录会拒绝覆盖；再次运行用新的目录即可。

| 样例 | 检查什么 | 预期结果 |
| --- | --- | --- |
| keys | 创建角色、导入双方旧话，恢复后追问物品位置 | 蓝盒子；正式导入记忆进入Writer卡包且被采用 |
| names | 用户名字与角色小名在同一句出现 | 阿岚属于用户，海盐属于角色，两个属性分别保留 |
| updated_location | 旧位置、位置更新与无关饮品话题，追问当前位置 | 从实际交付卡包的发生顺序读到玄关红抽屉 |
| speech_is_not_execution | 旧回复说“等会儿走过去递碗” | 保留已经说过的话，不生成已执行动作或动画回执 |

每个样例还会在“模型结果已封存、步骤检查点未写入”的位置注入一次异常，关闭并重新打开工作区。恢复后要求不增加提供方调用；正式发布也会分段、恢复和重复执行，检查没有重复事件。最后关闭重开正式存档，核对说话者、事件数量和未完成回复。

失败路径检查包含非法JSON量测后停止且不自动重发、未映射工具/媒体/重复来源ID拒绝，以及不能把第一只角色的来源回执用于第二只角色。

## 看结果与复用输入

- 总报告 `report.json` 列出每个问题、回答、实际交付的导入记忆ID和报告采用的ID。
- 各样例的 `chat.json` 是标准导入格式，可单独复制用于真实模型测试；`seed.json`、`work/`、`role/` 都是本次生成的离线示例资料。
- `speech.jsonl` 是样例执行器实际写入的文字文件，代表文件效果，不代表用户屏幕已显示或播放动画。
- 样例规格见 [petlab-cases.json](../../examples/petlab-cases.json)。其中 `fixture_facts` 是明确声明的合成量测输入，`questions.properties.expected` 只用于事后断言。离线Writer只能读取本次实际交付的卡包；卡包缺失时会报错，不能从预期答案直接作答。

要测试真实模型，请用自己的角色配置和生成的 `chat.json` 按 [导入教程](import-chat.md) 新建另一份工作区。离线示例配置的提供方地址只是占位，不能直接用它发真实请求。真实模型测试会产生费用，也可能出现归属或解析错误；这套离线样例不证明模型的理解质量、回复语气或动画观感。

## 运行自动回归

```powershell
.\.venv\Scripts\python.exe -B -X utf8 -m unittest examples.test_examples examples.test_petlab_scenarios
```

自动检查会禁止socket连接，并额外验证“没有实际交付的记忆就不能生成样例答案”。修改字段、属性路径或合同后，可以先跑这条命令。GitHub的Windows安装检查也运行同一组样例回归。
